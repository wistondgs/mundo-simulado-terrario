# World2D renderer

The native interface is `initialize`, `resize`, `setCamera`, `renderFrame`, `pick`, `dispose`, and `metrics`. Canvas2D is the permanent fallback and renders exact agent channel zero plus mask rather than pretending the observation contains world objects. WebGL2 uses capacity-grown reusable GPU buffers (`bufferSubData` per frame, rather than a new typed array and allocation per paint) and point rendering for world entities. Both renderers maintain a presentation-only coordinate index for O(1) picking rather than scanning every visible object.

Context loss or local renderer failure replaces only the affected renderer with Canvas2D. rAF presents the newest logical frame; authoritative events remain in the reducer/timeline.

The 2026-09-13 integrated matrix establishes a deliberate policy, not an assumption: Canvas2D remains the product primary for the complete three-view surface because it renders the exact Agent channel/mask representation and sustains 37.0 FPS at 10k entities/three views in both official browsers. WebGL2 has a materially lower presentation CPU cost (59.9 FPS Chromium and 58.8 FPS Firefox at that workload) and remains an available accelerated path with Canvas fallback. It is not silently promoted over Canvas until Agent-channel/mask visual and keyboard-picking parity are proven; a faster point-only rendering path must not weaken the observation contract. At 50k/three views neither implementation meets 30 FPS; the quantitative boundary and raw percentiles are recorded in `WORLD2D_PERFORMANCE_REPORT.md`.
